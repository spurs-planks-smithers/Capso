# Research note 01: Visual marks, crops, and coordinates in multimodal models

Date: 2026-11-01. A research agent (Sonnet) wrote this note for the visual direction study. It is raw evidence, not a decision. The synthesis is `docs/research/2026-11-01-visual-direction-research.md`. Numbers are as the agent read them; the synthesis marks the findings that were checked by hand.

Outcome: the strongest 2024 to 2026 evidence says mark style matters but is model-specific, text beside the mark helps, and crops help most for tiny targets on weaker or older models. No study tests "annotated vs clean vs both". I opened every source listed. Read-only research, no files edited.

## 2. Contradictions and open questions

1. **Crop gains may shrink on frontier models.** ViCrop, ZoomEye, and DeepEyes gains come from low-resolution or open models. BenchLM (aggregator, snapshot 2026-10-29) lists ScreenSpot-Pro: Claude Opus 4.5 45.7, Opus 4.6 83.1, Opus 4.8 87.9, Gemini 3.1 Pro 84.4, GPT-6 Astra 92.7. It warns that cropping, search, tools, and resolution make rows not comparable [15]. HiDe (ICML 2026 per arXiv; Qwen and InternVL only) says background clutter, not object size, is the main cause [9]. A crop may help by removing clutter.
2. **Marks vs text.** SeeAct: set-of-mark annotation loses to textual choices. Ferret-UI 2: GPT-4o referring 56.47 (red box) vs 87.91 with SoM prompt; text-coordinate grounding 12.14 [5]. Tasks differ and both use 2024 models. No data on Claude reading badges.
3. **Mark ranking is unstable.** ViP-LLaVA puts ellipse and rectangle on top. VP-Bench puts BBox on top. Feng et al. show model ranks flip with color or shape. In VP-Bench, GPT-4o with the best-perception shape vs a random best shape moved Mapillary Vistas by -10.89 and MIA by +6.35, so the general favorite may not suit your task.
4. **Order.** Anthropic says images first. Gemini says text first for one image. Tian et al. show position bias. No data for coding agents.
5. **Extra images.** MIMIC (abstract only) says cross-image aggregation is weak, which argues against clean plus annotated plus crop. Anthropic says do not crop away context. Test it.

Gaps: OpenAI's "thinking with images" post returned 403 (o3 evidence is press plus the DeepEyes table). Alpha-CLIP's PDF returned 403 and the AAAI page was blocked, so I found no direct evidence on marks damaging pixels. ScreenAI: abstract only (no small-text numbers read).

## 3. Three changes to test first

1. **Image-set arms.** A: annotated only. B: annotated plus clean (today). C: annotated plus item crop. D: annotated, crop, and clean. Cut the crop from the clean PNG, 1024 px square centered on the badge, clamped to the capture. Add a second crop size of 768 px. Label each image and print the crop offset. Measure: top-1 and top-3 file hit rate against the file the real fix touched, on 60 to 100 of the 270 items. Stratify by deictic instruction (53%), no instruction (16%), and target under 0.5% of image area. Run 3 runs per arm on Claude Code and Codex. Use a paired bootstrap CI and record tokens. Adopt the crop if it gains 5 points on the small-target stratum with a CI above zero at under 1.3x tokens.
2. **Badge style.** Compare today's badge with larger digits (1.5x), a white outline ring, a label offset to the bottom-left of the target, and a contrast color vs red. Measure two things. First, a badge-read probe ("list each badge and the text under it"), scored by exact match to the OCR text. Second, the same file hit rate as test 1. Report the mean and the worst variant across agents, as Feng et al. advise.
3. **Text-side frame.** Variant Y adds "Image 1 is W x H px. Boxes are x1,y1,x2,y2 in Image 1 pixels" and "Image N:" labels, with images first. Variant Z is Y plus an export sized to the model tier (1,568 px long edge) so the server never resizes. Measure a coordinate-echo probe (ask the agent to restate item N's box in Image 1 pixels, score pixel error) and the file hit rate. Use captures larger than 1,568 px.
