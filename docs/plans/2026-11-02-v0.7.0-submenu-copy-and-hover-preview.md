# v0.7.0 release candidate: copy from the round submenu, hover preview

Date: 2026-11-02. Requested by Drew. Status: plan, all questions answered, waiting for approval to start. No product code is written yet.

## Goal

A reviewer opens Recent Rounds, picks a round, and works inside that round's submenu. Two gaps cost them time today.

1. Checking a capture in the submenu gives no way to copy it there. The Copy N Selected row sits in the top-level menu, so the reviewer backs out of the submenu to use it.
2. A capture row shows a 40 by 26 point thumbnail. The reviewer cannot read the marks on it. The only larger view is Option-click, which closes the menu.

## Decisions (Drew, 2026-11-02)

| Question | Answer |
| --- | --- |
| What the submenu copy row copies | The whole selection, across rounds. Same prompt as the top-level Copy N Selected, same count in the title. |
| Where the rows sit | At the top of the submenu, above the capture list. |
| Preview size | Large, beside the menu: the annotated image fitted into 640 by 480 points. |
| Hover target | The whole capture row. |
| Row layout | Always present, gray when nothing is checked. |
| Hover delay | More than one second, then the preview shows until the mouse leaves (Drew's words). |
| Preview content | The annotated PNG (`capture.imageFile`). |

## Rows that appear while the menu is open (Drew, 2026-11-02)

Rows that appear on the first check would push the capture list down under a still pointer, so a second click could hit the wrong capture. Drew chose rows that are always present.

With nothing checked they are gray and show "Copy Selected", "Zip Selected" (only with `zipHandoff` on), and "Clear Selection". A check enables them and puts the count in the titles. Nothing moves. The cost is three extra gray rows in each submenu.

## Hover target (Drew, 2026-11-02)

The whole capture row starts the timer, not only the thumbnail. The preview can then pop when the pointer pauses on any row for a second. To limit surprise, the timer restarts each time the pointer moves to another row, and a click on the checkbox cancels a pending preview that has not shown yet.

## Design

### A. Selection rows in the submenu

- `FeedbackStatusItem.fillSubmenu` adds the rows, then a separator, above the capture rows. They reuse `copySelected`, `zipSelected`, and `clearSelection`, so the prompt, the zip, the clearing of the basket, and the one-zip-at-a-time beep stay in one place.
- A pure model in FeedbackKit (`SubmenuSelectionRows`) takes the basket count and the zip flag and returns each row's title and enabled state. The status item only applies it.
- `basketDidChange` retitles and enables or disables these rows in every open round submenu. It does not insert or remove rows, so no row moves under the pointer.
- The top-level basket lines stay as they are.
- The hotkey-free copy path keeps its rule: Copy N Selected clears the checks after it copies. The summary name request starts as it does today (`FeedbackSessionSummary`).

### B. Hover preview

- `FeedbackCaptureRowView` gets an `onHover` callback with the capture key and the row's screen rectangle, and an `onHoverEnd` callback. The trigger is the whole row. Its tracking area already exists, so `mouseEntered` and `mouseExited` feed the callbacks.
- `FeedbackHoverPreview` (new file in `App/Feedback/`) owns one borderless, non-activating `NSPanel`: level one above pop-up menus, ignores mouse events, `sharingType = .none`. No fade (my call during the build: a fade that fails to run during menu tracking would leave the panel invisible).
- The delay timer must run in the common run loop modes. Menu tracking runs in event tracking mode, and a default-mode timer never fires while a menu is open. This is the most likely failure, so a test covers the timer mode choice and the live check covers it again.
- When the timer fires, the image decodes off the main thread with ImageIO, capped at 1280 by 960 pixels (twice the point box), and shows only if the pointer is still on the same thumbnail. A small `NSCache` keeps the last few previews.
- A pure policy in FeedbackKit (`HoverPreviewPolicy`) holds the delay (1.0 second), the fit of an image size into the 640 by 480 box, and the placement: right of the submenu window, else left, clamped to the display's visible frame, aligned to the thumbnail's vertical center and then clamped.
- The preview hides on mouse exit, on the submenu closing, on the menu closing (`menuDidClose`), on Option-click Quick Look, and when a new thumbnail starts its own timer. A click that checks the row does not hide it.
- A missing or unreadable file shows no preview and no beep.

### Local only

No network code. The preview reads one file from the round folder. `NetworkSourceScanTests` stays green with no exception. Nothing is written to disk and nothing is logged beyond a debug line without file names.

## Tests

- FeedbackKit unit tests (the logic, no UI): row titles and enabled state for counts 0, 1, and many, with and without zip; fit for wide, tall, tiny, and zero-size images (a tiny image is not upscaled past its size); placement for each screen edge and for a preview taller than the screen; the delay constant; the timer mode choice.
- `swift test --package-path Packages/FeedbackKit`, then the app tests from AGENTS.md, then JevKit in Release before the trial build (project rule).
- Live check in Nextshot Dev only (m5pro rule), with `python3 -I scripts/nextshot-local.py check` first. Computer use cannot open Nextshot menus (memory), so Drew runs this checklist and I confirm by logs and `pbpaste`:
  1. Open a past round's submenu. Check two captures. The rows enable and no row moves.
  2. Copy Selected from the submenu. `pbpaste` shows one combined prompt. The checks clear.
  3. Hover a thumbnail for just under one second, then leave. No preview.
  4. Hover for more than one second. The large preview shows, marks visible, fully on screen.
  5. Move to another thumbnail. The first preview goes away, the second shows after its own delay.
  6. Test at the right edge of the display, and with a second display.
  7. Option-click still opens Quick Look. Esc and Return in the menu still work.
